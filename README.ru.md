# VeriPy

[English](README.md) · Русский

**Автоматизированное тестирование REST API на Python и pytest.**

VeriPy — фреймворк автоматизированного тестирования API
бронирований Restful Booker. Проект покрывает авторизацию, операции CRUD,
контроль доступа, фильтрацию, проверку схемы ответов и полный жизненный цикл
бронирования.

Сейчас pytest собирает **25 тестовых случаев**, включая параметризованные
сценарии. Тесты отправляют реальные HTTP-запросы, генерируют собственные данные
и удаляют созданные записи через фикстуры. Плагины pytest позволяют запускать
тесты параллельно и повторять их заданное количество раз.

Возможности тестируемого сервиса описаны в
[документации Restful Booker API](https://restful-booker.herokuapp.com/apidoc/index.html).

## Технологии

| Инструмент | Назначение |
| --- | --- |
| Python | API-клиент, фикстуры и тестовые сценарии |
| pytest | Запуск, проверки, фикстуры и параметризация |
| requests | HTTP-запросы с явно заданными тайм-аутами |
| Faker и UUID | Генерация данных бронирования и уникальных имён |
| jsonschema | Проверка обязательных полей, типов и формата дат |
| pytest-xdist | Параллельное выполнение тестов |
| pytest-repeat | Повторные запуски для исследования нестабильных ошибок |
| GitHub Actions | Автоматический и ручной запуск тестов в CI |

## Быстрый старт

Понадобятся **Python 3.13**, Git и доступ к публичному учебному API через
интернет. Выполняйте команды в терминале.

### Windows PowerShell

```powershell
git clone https://github.com/DenisBogdanenko/VeriPy.git
cd VeriPy
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -v
```

Если проект уже есть на компьютере, откройте его корневую папку и при
необходимости создайте виртуальное окружение. Команды обращаются напрямую
к Python из `.venv`, поэтому активация окружения необязательна.

### Linux и macOS

```bash
git clone https://github.com/DenisBogdanenko/VeriPy.git
cd VeriPy
python3.13 -m venv .venv
.venv/bin/python -m pip install -r requirements.txt
.venv/bin/python -m pytest -v
```

В PyCharm откройте корень репозитория и выберите `.venv` в качестве
интерпретатора проекта. Примеры команд выполняйте в терминале из этой папки.

## Запуск тестов

Далее приведены команды для Windows PowerShell. Для Linux и macOS используйте
`.venv/bin/python` вместо `.\.venv\Scripts\python.exe`.

### Просмотр тестовых случаев

Команда выводит список собранных случаев без отправки запросов к API.

```powershell
.\.venv\Scripts\python.exe -m pytest --collect-only -q
```

### Запуск файла или отдельного теста

```powershell
.\.venv\Scripts\python.exe -m pytest tests/test_get_booking.py -v
.\.venv\Scripts\python.exe -m pytest tests/test_booking_flow.py::test_booking_lifecycle -v
```

### Параллельный запуск

Параметр `-n` задаёт количество рабочих процессов.

```powershell
.\.venv\Scripts\python.exe -m pytest -n 2 -v
```

Например, `-n 10` запускает десять процессов. Каждый тест получает собственные
данные, а запросы внутри одного теста выполняются в заданном порядке.
Фактическое время выполнения зависит от скорости и доступности API.

### Повторные запуски

Команда запускает каждый тестовый случай пять раз, распределяя работу между
двумя процессами.

```powershell
.\.venv\Scripts\python.exe -m pytest -n 2 --count=5 -v
```

При 25 собранных случаях получится 125 выполнений. Для пяти последовательных
полных проходов используйте повторение сессии и отключите параллельный запуск.

```powershell
.\.venv\Scripts\python.exe -m pytest -n 0 --count=5 --repeat-scope=session -v
```

Добавьте `-x`, чтобы остановить прогон при первой ошибке или падении.

## GitHub Actions

Workflow `API tests` автоматически запускается при отправке изменений в `main`
и при создании или обновлении pull request в эту ветку. Он устанавливает
зависимости и запускает тесты на Ubuntu с Python 3.13 в двух процессах pytest.

### Запуск тестов из браузера

1. Откройте [workflow API tests](https://github.com/DenisBogdanenko/VeriPy/actions/workflows/tests.yml).
2. Нажмите **Run workflow**, выберите ветку `main` и ещё раз нажмите **Run workflow**.
3. Откройте новый запуск, выберите **api-tests** и раскройте шаг **Run API tests**,
   чтобы посмотреть вывод pytest и подробности ошибок.

Зелёная галочка означает успешный запуск, красный крестик — неуспешный.
Для ручного запуска войдите в GitHub с учётной записью, у которой есть право
записи в репозиторий.

## Настройки

| Параметр | Значение |
| --- | --- |
| `BOOKER_BASE_URL` | По умолчанию `https://restful-booker.herokuapp.com` |
| Имя пользователя учебного сервиса | `admin` |
| Пароль учебного сервиса | `password123` |
| Тайм-аут подключения и ожидания данных | `10` секунд |

Перед запуском можно задать другой адрес API в текущем терминале PowerShell.
Выбранный сервис должен поддерживать эндпоинты Restful Booker и учебную учётную
запись, которую использует фикстура авторизации.

```powershell
$env:BOOKER_BASE_URL = "http://localhost:3001"
.\.venv\Scripts\python.exe -m pytest -v
```

В Linux и macOS переменную можно задать для одной команды.

```bash
BOOKER_BASE_URL=http://localhost:3001 .venv/bin/python -m pytest -v
```

Для этих примеров нужен работающий экземпляр Restful Booker по указанному
адресу. Учётные данные сейчас заданы в `conftest.py` и тестах авторизации.

## Покрытие тестами

| Область | Случаев | Проверки |
| --- | --- | --- |
| Доступность | 1 | Проверка работоспособности API |
| Авторизация | 2 | Выдача токена и неверный пароль |
| Создание бронирования | 8 | Корректные данные, отсутствие обязательных полей и дат |
| Получение бронирований | 4 | Список ID, чтение по ID, JSON-схема и фильтрация по имени |
| Обновление бронирования | 6 | PUT и PATCH, сохранение изменений, отсутствие или неверный токен |
| Удаление бронирования | 3 | Успешное удаление, отсутствие или неверный токен |
| Жизненный цикл | 1 | Создание, чтение, PUT, PATCH, удаление и проверка отсутствия |
| **Всего** | **25** | |

Проверка схемы входит в тест чтения по ID. Разные значения параметризации
считаются отдельными тестовыми случаями.

- `api/` формирует HTTP-запросы и возвращает ответы для проверок в тестах.

## Данные и очистка

Каждый тест, который запрашивает `booking_data`, получает новый набор данных.
Имя гостя содержит UUID, цена выбирается в диапазоне от 100 до 200, а выезд
назначается через два дня после заезда.

Фикстура `created_booking` получает токен и создаёт запись перед тестом.
После выполнения теста она проверяет существование записи и удаляет её
с действительным токеном. Если тест уже удалил запись, фикстура принимает её
отсутствие. Очистка выполняется и после падения проверки внутри теста.

## Как интерпретировать результат

Тесты учитывают особенности ответов выбранного API.

| Сценарий | Ожидаемый ответ в текущих тестах |
| --- | --- |
| Проверка доступности | HTTP `201` |
| Успешное создание | HTTP `200` |
| Успешное удаление | HTTP `201` |
| Неверный пароль | HTTP `200`, поле `reason`, отсутствие токена |
| Защищённая операция без действительного токена | HTTP `403` |
| Чтение удалённой записи | HTTP `404` |
| Создание без обязательных данных | HTTP `500`, `Internal Server Error` |

Тесты с отсутствующими данными фиксируют наблюдаемый ответ учебного API
с серверной ошибкой. Они описывают его текущее поведение. Качество обработки
ошибок рассматривается отдельно при исследовании дефектов и оформлении
баг-репортов.

Публичный сервис используется совместно с другими пользователями и может
сбрасывать записи. Сброс между созданием и чтением может привести к падению
теста. Сетевые сбои и ответы HTTP `503` также могут вызвать ошибки теста или
очистки. Если очистка завершилась ошибкой, тестовая запись может остаться
в сервисе.

При неуспешном прогоне посмотрите на этап сбоя и HTTP-ответ. Ошибка подготовки
или очистки фикстуры указывает на другой шаг, чем падение проверки внутри
теста. Для исследования воспроизводимости запустите проблемный случай
отдельно. Точный идентификатор теста pytest выводит в итоговой сводке.
